# 审计日志内容展示与核对

审计详情将展示用途与核对用途分开，不把格式化数据称为原始 HTTP 内容。

## 可读视图

- 请求按消息列表展示，响应按保存的摘要展示；长消息默认显示截断预览，展开后显示完整字段内容。
- 正文与明文推理内容仅按 JSON 解析结果展示和复制，不再二次反转义。Windows 路径、正则、字面 `\n` 与实际换行保持区别。
- 工具参数允许展开字符串内的换行等转义，便于阅读脚本和补丁。这种可读结果不保证是合法 JSON，也不能作为原文核对依据。
- 工具卡片的「复制原文」复制解析后的参数字符串，不做二次转换；「复制可读内容」复制格式化展示结果。非字符串参数明确使用「复制参数 JSON」。
- 「请求 JSON（格式化）」与「响应摘要 JSON」可能重新序列化；对应按钮明确标注「复制格式化 JSON」。工具调用 JSON 也是格式化展示，协议归一后的结构不代表原始工具对象。

## 源数据

- 请求直接展示和复制数据库 `request_body` 字符串，包括保存的空白、转义和行尾，不重新 JSON 序列化。
- 响应优先按 `seq` 拼接数据库 `stream_segments.content`，不增加分隔符、不解析或反转义 SSE。
- 没有保存 SSE 时，仅提供数据库 `response_choices` 的摘要存文，并明确提示「未保存下游 SSE」。不会拿重新生成的摘要冒充响应原文。
- SSE 加载中或加载失败时单独提示，失败可重试，不把加载失败当成未保存。

## 边界与限制

这里的原文指**保存的数据或解析后的参数字段**，不是网络原始字节：

- 请求入库前经过日志脱敏和 JSON 序列化，简要级别还可能裁剪消息；裁剪数量由现有标记提示。安全扫描的「已脱敏」标志不能说明日志存储没有另外脱敏。
- 响应摘要由响应提取重组，工具调用可能归一到 `function/tool_calls`。
- SSE 是网关保存的下游输出，可能已转换协议。异常中断的日志可能只有已生成部分。
- 加密推理字段仍是上游提供的密文，源数据视图不会也不能将其恢复成明文。
- 本次优化不修改网络转发、后端入库内容、脱敏策略或数据表，不补录历史日志丢失的内容。
