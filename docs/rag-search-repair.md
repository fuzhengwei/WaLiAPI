# RAG 中文文本与向量召回修复

PDF 文字层有时会把“日、方”等汉字提取为外观相近的部首“⽇、⽅”。旧版查询端生成中文双字词，但 FTS5 文档端仍索引整段连续中文，导致“日志、方法”等正文存在的词无法命中。此外，向量索引的结果堆方向与候选堆相同，容量满时可能丢弃最近邻；近邻图也可能存在互不可达的簇。

本次调整：

- PDF 文字层和 OCR 结果在切片、哈希与向量化之前折叠部首字形。只修复部首，不对 PDF 中的代码示例整段做 NFKC；代码文件的原文也保持原样。
- Embedding 公共入口对查询及待嵌入文本统一折叠部首，覆盖管理命令、REST、MCP 等调用方。
- 独立的 `search_text` 仅用于关键词索引，使用 NFKC 和中文重叠双字词。文档和查询共用分词器，文档额外保留单字词；MATCH 中的词保持引用，查询去重并限制为 64 项。
- 向量候选堆保持最近者优先，结果堆改为最远者优先；墓碑节点计入搜索候选预算。
- 全量构建、增量插入和现有格式索引加载时保留相邻节点双向骨架，避免分离簇和新增节点不可达。邻接表最多为近邻数 M 加两条骨架边。序列化格式未改变；更早的不可读格式仍沿用原有线性检索/重建回退。
- 物理节点不超过 1024 的索引直接做精确余弦排序；更大索引保留图搜索。这是小库的正确性保障，不代表大库的近似召回率达到 100%。

## 已有知识库如何升级

迁移 `037_kb_search_projection.sql` 新增检索投影列和待补建索引。应用在原有迁移前备份流程之后执行迁移，启动时每批 128 个切片补建关键词投影；中断后从 NULL 投影继续。后续正文变更会让投影失效，在下次关键词检索前补建。

补建关键词投影不修改历史正文、内容哈希或向量，也不调用 Embedding 服务。因此，安装修复版后，历史切片中的“⽇志”可以被“日志”查询检索到，但历史正文不会自动改字。

要同步修复已有 PDF 的正文和对应向量：在知识库“文档”列表使用现有的重新处理按钮。原文件必须仍存在，Embedding 渠道必须可用；按原有流程重新解析、切片、向量化，并更新索引。内容发生变化的切片会得到新哈希，不会误用旧内容的向量。仅执行“构建索引”不会重新解析 PDF，也不会修复正文。

本次不改变 RAG 访问凭据、网关模型配置或统计口径，不会自动重摄入全部文档。

## 验证

在 `src-tauri` 目录运行：

```sh
cargo test --lib services::knowledge
cargo test --test rag_search
```

回归覆盖结果堆溢出时保留最近邻、簇间连通性、旧图加载修复、远端增量插入、大图墓碑过滤、小库精确排序、空重建、PDF 部首折叠、代码字面值保留，以及真实 SQLite 旧版迁移、中文关键词命中、知识库/文档状态隔离、投影幂等补建和更新/删除同步。

`rag_search` 使用合成数据和内存 SQLite，不依赖个人账号、付费模型或私有 PDF。关键词能命中与题目答案正确率是不同指标；升级后仍应使用独立样本检查 RAG 问答质量。
